## Local acquisition evidence

The audit records byte counts and SHA-256 for available local copies in `dataset_manifest.json`. These values identify the files that were audited; they do not prove an official source revision. PhishVN's included `MANIFEST.txt` checks file hashes against the archive's own manifest. That verifies archive internal consistency, not the download channel or publisher identity. No official PhiLegit CSV/README payload was downloaded. The local LegitPhish candidate has a `URL` column plus engineered features; only the URL string is potentially suitable for the existing character model, and the local file identity remains unverified.

Mendeley documents OAuth for dataset file metadata/download endpoints in its [API documentation](https://data.mendeley.com/api/docs/). This workflow stopped at that access requirement and did not use credentials or bypass it.

## Inventory interpretation

`overlap_results.json` contains machine-generated schemas, counts, missingness, URL duplicate counts, ambiguous-label counts (only where mappings are documented/provisionally provided), source/tier counts, timestamp parsing, PhishVN split counts/overlap checks, and pairwise hashed-set overlaps. The local PhishVN URL table has 53,116 rows and normalized labels `benign=0: 16,410`, `phishing=1: 36,706`; this is the publisher's broader abuse/phishing meaning, not a credential-phishing equivalence. Its supplied train/validation/test split counts are 36,909/7,266/8,941. AnaRisk-normalized URL and domain crossover among those split assignments was zero. This verifies only the local table's grouping structure, not independence from Mitake or target validity for AnaRisk.

The auditor uses AnaRisk's `normalize_url` function and Mitake's `domain_group`/bundled `tldextract` PSL snapshot with online suffix fetching disabled. No raw URL, host, query, credentials, or row-level hash is written.

The audit normalizes candidate URL values for comparison. It does not establish original URL equivalence under all upstream preprocessing and does not upgrade an unauthenticated local file's provenance. In the local PhishVN table, `collected_at` has 17,048 parseable values from 2021-05-07 through 2024-05-16, with 36,068 missing/invalid; docs describe it as a source-recorded detection/certification date. `scraped_at` parses for all 53,116 rows from 2026-07-10 through 2026-07-16; docs describe this as scrape/acquisition time, not event time. Undated benign examples prevent a fully chronological all-record split. For PhiLegit and local LegitPhish, no reliable per-row timestamp is established.
