# AnaRisk Round 2 implementation map

## Repository audit

This is an extension of the existing React/Vite, FastAPI, SQLAlchemy/Alembic, PostgreSQL application. Round 1 already has authenticated brand-scoped APIs, role permissions, normalized digital entities, registered brand references, evidence records, immutable risk assessments, four provenance-aware detector families, a paginated detections view, investigation cases with status/assignment/note/event history, in-app notifications, and aggregate/CSV reports. The local seed data is explicitly synthetic. External social/app connectors are stubs unless configured.

Key files: `backend/app/models/{brand,entity,case,notification}.py`; `backend/app/services/{analysis,scoring,official,cases,notifications,reports}.py`; `backend/app/api/v1/{detection,cases,notifications,reports}.py`; `backend/alembic/versions`; `frontend/src/pages/{ThreatIntelPage,CasesPage,CaseDetailPage,AlertsPage}.tsx`; `frontend/src/services`.

## Requirement map and implementation decisions

| Round 2 area | Existing implementation | Round 2 extension / remaining boundary |
|---|---|---|
| Detection records and evidence | `DigitalEntity`, immutable `RiskAssessment`, `DetectionSignal`, evidence refs, timestamps, provenance and actor are persisted. | Reuse these IDs/history and case links; do not create fake platform observations. **Detection record exposed (slice 1):** the detection list/detail entity ref now carries `source_url`, `first_seen_at` and `last_seen_at`, and each detection carries `matched_official_asset_id` (the registered brand reference a signal actually matched, when any — safe UUID coercion, `NULL` otherwise). `ThreatIntelPage`'s detection modal renders a **Detection record** section with the source link, first/last seen and the matched official asset. |
| Explainable scoring | Four configurable heuristic families, effective-weight renormalization, unavailable signals, confidence separate from risk, and model detail API. | Existing formula does not yet implement the requested five named weights or the 0–100 presentation. It remains labeled heuristic pending a compatible detector-level migration. **Added the report's coverage rule as an additive marking:** `SCORING_COVERAGE_FLOOR` (default 0.60) compares the sum of observed weights against the floor; `confidence_breakdown` now carries `coverage`, `coverage_floor` and `provisional`, thin-evidence runs get an explicit "Provisional" note, and the detection detail shows a provisional banner. Scores are never zeroed or hidden. |
| Official assets | Brand references and stable domain/handle/package comparisons; official entities are blocked from scoring. | Keep the existing guard and regression coverage; ambiguity remains explicit when references are absent. **Verified (slice 1):** brand references are stampable as reviewed — `verified_by` / `verified_at` / `verification_source` (migration 0013), written on both creation paths (manual add and image upload). The guard itself is unchanged: exclusion always matches a registered identity, never display-name similarity (the evaluation fixture's `publisher-difference-app` pins this). |
| Side-by-side evidence | Detectors already persist comparison pairs in signal `meta` (`field` / `value` / `official` / `similarity` / `reason`; logo: perceptual-hash `top_matches`). | `ThreatIntelPage` now renders an **Official vs. observed** table in the detection detail modal (observed value beside the registered official value, similarity bar, and how it was measured). The bio match in `detection/impersonation.py` now stores both sides verbatim (it previously stored only the official side, truncated), so older analyses show a "literal not stored" placeholder until re-analyzed. |
| Investigation dashboard | `/detections` and `/cases` provide filters, sorting, pagination, loading/error/empty states and evidence detail. | The investigation workflow is case-centered; case history is append-only. **Worklist:** the cases page now exposes the already-supported `mine` / `unassigned` assignee filter, and `risk_score` sorting ("most concerning first") was already available on the Risk column. |
| Analyst decisions/history | RBAC-protected case status transitions, decisions, notes, assignments and actor/timestamp events. False positives are a resolution outcome. | Case workflow covers the existing labels; it does not yet expose the exact standalone detection statuses requested. **Reopen fix:** the server requires a comment to reopen a resolved case but the UI never sent one (guaranteed 422); `CaseDetailPage` now opens a Reopen modal that collects the reason and sends it with `expected_status`. **Response outcomes (slice 2):** what was DONE about a threat is tracked separately from the analytical disposition — `POST /cases/{id}/response-outcome` records `no_action / report_drafted / report_submitted / removal_observed` (`response_outcome*` columns + `ck_case_removal_evidence`, migration 0014), gated by `case:resolve` with brand-scoped evidence validation. `removal_observed` requires verification evidence (422 otherwise). Each write appends a `response_recorded` timeline event (payload in `details` only — never `from_status`/`to_status`; enum added in migration 0015) and a `case.response_outcome` audit row. The case page's **More menu** records/updates the outcome (evidence picker fed by case-linked evidence when removal is selected) and the details card shows outcome + actor + timestamp. |
| Takedown report | No record-specific report draft existed. | `GET /cases/{case_id}/takedown-report` requires `case:resolve`, only serves confirmed resolutions, and returns a draft from linked entities, assessments, brand references, case evidence and history. The case page supports preview, copy and download. No external submission. **Fixed:** the draft crashed on `SignalOut.meta` (the attribute is `metadata`) and its `submission_note` silently fell back to the schema default that did not state the no-submit boundary; both are now explicit. |
| High-risk alerts | Notifications previously deduplicated by entity and a 24-hour window. | `high_risk_alerts` now stores a unique alert per assessment ID and scoring-rule version. Notifications link to that detection and remain read through the existing notification interface. Official assets are checked before creating either alert or notice. |
| Evaluation (Phase 5) | — | `backend/tests/fixtures/evaluation/round2_eval_set.json` is a labeled **synthetic** set (17 items) covering all eight required categories: official assets, close-copy scams, harmless look-alikes, fan/parody, app publisher differences, missing evidence, multilingual names and duplicate observations. Labels are authored ground truth, independent of the score rules; fixture loading rejects unlabeled/non-synthetic items and any official labeled as a threat. `app/evaluation/` runs the fixture through the **production** `is_official_asset()` guard and `compute_score()` (four-family model, coverage floor intact), collapses duplicate identities, ranks deterministically, and reports: Precision@10 with actual k, recall at the configured medium threshold, step-wise average precision (sklearn's binary-AP definition, implemented without new dependencies), zero-verified-officials-in-queue with inventory coverage reported separately, and evidence completeness with per-field missing counts. Runnable measurement: `python scripts/evaluate_ranking.py` (exits 1 if a verified official reaches the queue). Test coverage: `tests/test_evaluation.py` (metric units + fixture invariants). |
| API, UI, migrations | FastAPI, React services, Alembic, organization scoping and RBAC are established. | Added additive migrations: `0012` (durable alert rows), `0013` (brand-reference verification stamp), `0014` (case response outcome + `ix_cases_response_outcome` + removal-evidence CHECK/FKs), `0015` (case-event type value `response_recorded` — CHECK rebuilt with `op.f()` so the naming convention cannot double-prefix it), `0016` (value-list CHECK for `response_outcome`, closing the every-enum-column-has-a-CHECK invariant that migration 0014 left open). `docs/API.md` regenerated from the OpenAPI schema (116 endpoints) with the two hand-enriched case rows preserved. `SCORING_COVERAGE_FLOOR` was added to `.env.example` (default 0.60, validated 0–1); no migration is required for the coverage marking because it lives in the existing `confidence_breakdown` column. |
