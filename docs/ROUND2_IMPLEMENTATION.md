# AnaRisk Round 2 implementation map

## Repository audit

This is an extension of the existing React/Vite, FastAPI, SQLAlchemy/Alembic, PostgreSQL application. Round 1 already has authenticated brand-scoped APIs, role permissions, normalized digital entities, registered brand references, evidence records, immutable risk assessments, four provenance-aware detector families, a paginated detections view, investigation cases with status/assignment/note/event history, in-app notifications, and aggregate/CSV reports. The local seed data is explicitly synthetic. External social/app connectors are stubs unless configured.

Key files: `backend/app/models/{brand,entity,case,notification}.py`; `backend/app/services/{analysis,scoring,official,cases,notifications,reports}.py`; `backend/app/api/v1/{detection,cases,notifications,reports}.py`; `backend/alembic/versions`; `frontend/src/pages/{ThreatIntelPage,CasesPage,CaseDetailPage,AlertsPage}.tsx`; `frontend/src/services`.

## Requirement map and implementation decisions

| Round 2 area | Existing implementation | Round 2 extension / remaining boundary |
|---|---|---|
| Detection records and evidence | `DigitalEntity`, immutable `RiskAssessment`, `DetectionSignal`, evidence refs, timestamps, provenance and actor are persisted. | Reuse these IDs/history and case links; do not create fake platform observations. |
| Explainable scoring | Four configurable heuristic families, effective-weight renormalization, unavailable signals, confidence separate from risk, and model detail API. | Existing formula does not yet implement the requested five named weights or the 0–100 presentation. It remains labeled heuristic pending a compatible detector-level migration. **Added the report's coverage rule as an additive marking:** `SCORING_COVERAGE_FLOOR` (default 0.60) compares the sum of observed weights against the floor; `confidence_breakdown` now carries `coverage`, `coverage_floor` and `provisional`, thin-evidence runs get an explicit "Provisional" note, and the detection detail shows a provisional banner. Scores are never zeroed or hidden. |
| Official assets | Brand references and stable domain/handle/package comparisons; official entities are blocked from scoring. | Keep the existing guard and regression coverage; ambiguity remains explicit when references are absent. |
| Side-by-side evidence | Detectors already persist comparison pairs in signal `meta` (`field` / `value` / `official` / `similarity` / `reason`; logo: perceptual-hash `top_matches`). | `ThreatIntelPage` now renders an **Official vs. observed** table in the detection detail modal (observed value beside the registered official value, similarity bar, and how it was measured). The bio match in `detection/impersonation.py` now stores both sides verbatim (it previously stored only the official side, truncated), so older analyses show a "literal not stored" placeholder until re-analyzed. |
| Investigation dashboard | `/detections` and `/cases` provide filters, sorting, pagination, loading/error/empty states and evidence detail. | The investigation workflow is case-centered; case history is append-only. **Worklist:** the cases page now exposes the already-supported `mine` / `unassigned` assignee filter, and `risk_score` sorting ("most concerning first") was already available on the Risk column. |
| Analyst decisions/history | RBAC-protected case status transitions, decisions, notes, assignments and actor/timestamp events. False positives are a resolution outcome. | Case workflow covers the existing labels; it does not yet expose the exact standalone detection statuses requested. **Reopen fix:** the server requires a comment to reopen a resolved case but the UI never sent one (guaranteed 422); `CaseDetailPage` now opens a Reopen modal that collects the reason and sends it with `expected_status`. |
| Takedown report | No record-specific report draft existed. | `GET /cases/{case_id}/takedown-report` requires `case:resolve`, only serves confirmed resolutions, and returns a draft from linked entities, assessments, brand references, case evidence and history. The case page supports preview, copy and download. No external submission. **Fixed:** the draft crashed on `SignalOut.meta` (the attribute is `metadata`) and its `submission_note` silently fell back to the schema default that did not state the no-submit boundary; both are now explicit. |
| High-risk alerts | Notifications previously deduplicated by entity and a 24-hour window. | `high_risk_alerts` now stores a unique alert per assessment ID and scoring-rule version. Notifications link to that detection and remain read through the existing notification interface. Official assets are checked before creating either alert or notice. |
| API, UI, migrations | FastAPI, React services, Alembic, organization scoping and RBAC are established. | Added additive migration `0012` for durable alert rows. The report endpoint reuses current tables. `SCORING_COVERAGE_FLOOR` was added to `.env.example` (default 0.60, validated 0–1); no migration is required for the coverage marking because it lives in the existing `confidence_breakdown` column. |

## Verification
